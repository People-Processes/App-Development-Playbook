Build it the same way

How we plan, write, build, verify and ship software. One standard for every internal product, from a one-line label fix to a whole new module.

A work item is a request for work, written before the work happens, in enough detail that a second person can build it and a third person can confirm it works.

App Development Playbook

The standard itself. Twenty sections covering intake, PRDs, the board, item types, writing, acceptance criteria, estimation, the Ready and Done gates, code and environments, releases, and building with AI. Interactive, with templates you can copy.

Where to start

New to the team

Read playbook sections 00 to 09 in order. Take the quiz at the end. Then read the Collaboration SOP so you know who to hand what to.

Filing work, not building it

Playbook sections 03, 04, 07, 08 and 09 are the ones that matter. Or skip straight to the Claude skills and let one draft it for you.

Building

All of it, and section 15 twice. Then the Collaboration SOP for the handoff contracts and the AI-pairing rules.

Setting up a new build

Start with the PRD template in playbook section 16, or ask Claude to write it. New PRDs live in /docs/prd/ in the product repo.
